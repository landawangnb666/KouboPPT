# 口播PPT (KouboPPT)

把 **扫描版教材 PDF 或现成 PPT** 一键变成成套课程资料的 Windows 桌面工具：

- **教材 → 课程**（两步环环相扣，可中途停下、可断点续跑）：
  1. 扫描 PDF 逐页识别（含公式转 LaTeX）→ AI 按目标时长生成 PPT 课件与口播稿 → 课件备注 TTS 配音合成口播视频（上一节的视频在合成时，下一节的课件已经在生成）
  2. 教材原文 → 学习笔记、题库导出 Word/PDF
- **PPT → 视频**：把现成 PPT 一键生成口播视频（自动提取文字/备注 → TTS → 合成 MP4），支持批量、按页码范围拆成一节节课

理工科公式专门处理：一律 LaTeX → 高清图片嵌入，PPT/Word 中不会出现乱码或公式源码。

## 下载安装

### 方式一：下载安装包（推荐）

到 **[Releases](https://github.com/landawangnb666/KouboPPT/releases)** 页面下载最新的 `KouboPPT_Setup_v0.4.0.exe`，双击 → 一路"下一步"装好（可勾选桌面图标），装完从桌面/开始菜单启动，控制面板里可卸载。**安装不需要管理员权限、不弹 UAC**，默认装到 `%LOCALAPPDATA%\Programs\KouboPPT`。

- 首次运行 Windows 可能提示"已保护你的电脑"——没有代码签名证书的软件都会这样，点"更多信息 → 仍要运行"即可
- 不想安装的人，可以下载 Releases 里的目录版压缩包，解压后直接双击 `KouboPPT.exe`（免安装，双击即用）

> **本仓库只托管源码**，不含 `dist/` 下的打包产物（安装包单个约 95 MB，超出常规仓库托管范围）。
> 若 Releases 页面暂时还没有安装包，按下文「[给开发者](#给开发者)」一节自行构建即可。

### 方式二：从源码运行

需要 Python 3.10 或更高（开发环境为 3.14）：

```bash
git clone https://github.com/landawangnb666/KouboPPT.git
cd KouboPPT
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python.exe run.py
```

源码运行同样需要本机装有 Microsoft PowerPoint 或 WPS 演示。

**使用环境要求（使用者的电脑）：**

- Windows 10/11
- 装有 **Microsoft PowerPoint 或 WPS 演示**（任选其一，用于渲染幻灯片；"Word 再转 PDF"需要 Microsoft Word）
- 联网（内置 TTS 是微软 Edge 语音云服务；AI 功能需要调用大模型接口）

## 一、教材 → 课程（新）

### 1. 配置 AI 引擎

在"教材 → 课程"页填写任意 **OpenAI 兼容接口**（DeepSeek、通义、Kimi、智谱、OpenRouter、本地 Ollama 均可）：

| 字段 | 示例 | 说明 |
|---|---|---|
| 接口地址 | `https://api.deepseek.com/v1` | 到 `/v1` 为止，程序自动拼 `/chat/completions` |
| 模型 | `deepseek-chat` / `qwen-vl-max` / `glm-4v` | **识别扫描页需要支持图片输入的多模态模型** |
| API Key | `sk-...` | 只保存在本机 `%APPDATA%\KouboPPT\config.json` |

点"测试连接"确认可用。整本教材的花费主要来自 OCR 识别（按页计费），生成内容花费较小；识别结果有缓存，见下文。

### 2. 选择教材并设置产出

1. **扫描版 PDF**：任意教材，扫描版/文字版都可以
   - 文字版页面直接抽取文字（免费、秒出）；扫描页自动逐页调多模态模型识别
2. **切分方式**（两种，按书的实际情况挑一种）：
   - **按每节页数**（默认）：从"起始页"开始，每 N 页一节课，自动一节接一节排到全书结束。例：300 页的书 + 每节 15 页 → 20 节课；除不尽时余数独立成最后一节
   - **按教材章节**：先拿到每章页码范围（优先读输出目录里的 `章节结构.json`，其次 PDF 书签，其次 AI 看前 20 页目录识别——低清缩图发送，超时自动换更小的请求重试），再在每章内部**沿目录小节边界**聚合成每节约 N 页的课（二级书签或 AI 识别的 1.1/1.2 都算小节；没有小节信息的章退回按 N 页均分），**绝不跨章**（≤N 页的章整章一节；单个小节就超过 N 页时独占一节但会均分成多块，标题带 i/n）
3. **起始页**：默认 1；填 6 表示从第 6 页开始切课，封面/目录跳过不识别、不花钱（仅"按每节页数"模式生效）
4. **每节页数**：默认 15（建议 10~30）。**最短节**默认 0（不合并）；填如 8 表示低于 8 页的短节自动并入相邻节——章首短节并入第二节、章尾短节并入上一节、整章只有一节仍短的并入相邻章，两种切分模式都生效
5. **每节时长**：默认 35 分钟（30~40 是推荐区间）。AI 会按此规划每节课的内容页数量（约 1.15 分钟/页），实际时长由讲稿字数决定
6. **PPT 风格**：默认「自动（AI 按书名选风格）」——按教材名让 AI 从风格库里挑 3 套候选；**分步确认模式下弹窗（每套带离线预览图）让你点选，全自动模式下不打扰、直接取 AI 首推**（命令行直接跑同理）；选中的风格记进书目录的 `PPT风格.json`，全书统一、重跑不再问 AI。也可以直接指定：学术蓝（数学/物理）、工业灰橙（机械/工科）、理科墨绿（化学/生物）、人文暖棕（文科/历史）、医学青蓝（医学/护理）、科技靛蓝（计算机/电子）、素白极简（通用）。**风格 = 配色 × 版式骨架**（页眉骨架：色带/侧栏/色块/极简；封面骨架：整幅/分栏/色块/极简），骨架只用色块与文字摆位实现——AI 只在风格库里**选**，不允许自造配色，保证质量下限；加新风格只需在 `slidegen.py` 的 `THEMES` 里加一条并补个中文名
7. **产出内容**：PPT 课件 / 口播视频 / 学习笔记 / 题库，可勾选"Word 再转 PDF"。题库**题量**（每节课）默认 15，下拉可选 5 / 10 / 15 / 20 / 30，选「自定义…」会出现输入框自己填（3~100）。另外**课后习题是白送的**：识别稿里若抄到了"课后习题/思考题"这类小节，会自动切出来单独出 Word（见下文输出结构），不额外花钱、也不占勾选项
8. **运行模式**（见下节）：分步确认（默认）/ 全自动
9. **视频编码**（见下文"软编还是硬编"）：和「PPT → 视频」页是同一个设置，两边下拉互相同步，改哪边都一样
10. TTS 音色与语速沿用"PPT → 视频"页里的设置

### 3. 运行模式：分步确认 / 全自动

两步之间以**文件**接力——每一步的产出就是下一步的输入，所以两步可以分开跑：

| 模式 | 行为 |
|---|---|
| **分步确认**（默认） | 一本书的所有课按步一次跑完，然后在步骤之间停一次，弹窗问「继续下一步 / 就到这里」（课件+视频做完后停一次，再问要不要做笔记题库）。 |
| **全自动** | 一口气跑完全部产出，中途不询问。 |

弹窗里的「就到这里」= 先停在当前步骤；随时再点一次"开始生成课程"就会**接着已有产物继续**（已完成的课不会重做、不会重复计费）。也可以借此单跑某一步：

- 只想重出视频：取消勾选 PPT / 笔记 / 题库，只留"口播视频"——已有课件会被自动复用；
- 只想出笔记题库：只勾"学习笔记 / 题库"，不会重新生成 PPT；
- 缺哪一步的前置产物（比如没有 `教材原文.md`），程序会自动补做那一步。

### 4. 提速：请求并发

整条流水线最慢的是等接口一个个响应，所以程序默认**同时发 4 个请求**：识别按页并发、课件按小节并发、视频按页配音并发、学习笔记与题库两路一起发。实测识别/生成这类"等接口"的环节能快到 2~4 倍，配音+编码环节约 1.5~2 倍（受本机 CPU 与网络影响，视频编码本身是 CPU 活）。

**视频与课件并行**：口播视频由 1 路后台队列合成——第 1 节的课件做完，它的视频就开始配音合成，同时程序继续做第 2 节的课件，不用等第 1 节视频出完。所以"课件+视频"两步的总耗时接近两者中较慢的那个（视频按书序出，不会乱序）。

**全自动模式下笔记/题库也和视频并行**：全部课件做完后不再等视频收尾，直接开始第二步的学习笔记 + 题库，剩下的视频在后台继续合成，最后统一收尾（日志会给出「口播视频收尾：共 N 个，其中 X 秒是第二步之后才等出来的」）。两边不打架的原因是：视频那条线只有幻灯片导出子进程、配音网络和 ffmpeg，不碰公式渲染（matplotlib 非线程安全，只在主线程建 pptx / docx 时用）。**分步确认模式不这样做**——闸门前必须把视频全部收完，否则你点"就到这里"时后台还在往输出目录写文件。中途出错或取消时，正在合成的那一节会立刻收到停止信号，排队中的直接丢弃，不会留下野线程。

**视频编码已经不是瓶颈**：帧率默认 10fps 后，一页 60 秒口播约 3 秒编完（30fps 时约 17 秒），视频这一步的时间几乎全花在配音的网络等待与幻灯片导出（PowerPoint/WPS COM）上。编码并发也无需再放开——实测软编 1 / 2 / 3 / 6 路耗时几乎相同（单个 x264 进程就已吃满全部核心）。基准脚本留在 `test_out/_bench_enc*.py`。

**软编还是硬编，由首启自检实测决定**：第一次启动会盖一层「本机视频编码自检」页，用一段 30 秒的测试画面把 CPU 软编（libx264）、NVIDIA（NVENC）、Intel 核显（Quick Sync）、AMD（AMF）各真编一遍，摆出实测耗时让你选，选完写进配置，之后不再打扰（「PPT → 视频」页和「教材 → 课程」页各有一个**视频编码**下拉，互相同步，可随时改，旁边都有「重新自检」）。测试片段必须够长：硬编每次起 ffmpeg 都要付约 0.7 秒硬件会话初始化开销，片段太短会把硬编冤枉死。没有对应显卡/驱动的候选自动归为"不可用"；自检也能跳过，跳过就用 CPU 软编。开发机（i5-12450H + Intel 核显）实测 30 秒片段：软编 1.12s、Quick Sync 1.98s → 推荐软编，但换到带独显的机器上结论可能反过来，所以让每台机器自己测。运行期还有兜底：某节硬编真编炸了，整节自动改回软编重做（配音有缓存，不重复合成）——concat 用 `-c copy`，混两种编码器的片段会拼出坏文件，所以不能只补失败那几页。

「运行模式」一行的**请求并发**下拉给了 2 / 4 / 6 / 8 这几个常用挡位（默认 4），**但不设上限**——鼠标点进框里把数字删掉、直接输入更大的数（比如 16、32）就生效：

- 被接口限流时（日志里出现"重试"、HTTP 429/524）调到 **2 路**；
- 想完全回到"一个请求接一个请求"的老行为，在框里直接输入 **1**；
- 输入非数字按 4 处理，填 0 或负数按 1 处理；
- 实际并行数还受任务规模限制：一节课只有 15 页时，识别最多 15 路；视频那一步的**编码**再按 CPU 核数封顶（网络配音不受此限），免得编码互相抢 CPU 反而更慢；
- 日志会给出耗时账：每节课打「本节用时 X 分 Y 秒」，整批结束打「总用时」和两步各自耗时（视频日志带 `[视频·N]` 前缀，和课件日志交错出现说明并行在生效）；
- 并发数不影响产物：先发的请求先完成、但结果一律按原顺序（页序/小节序）组装，1 路和 4 路出来的文件内容一致。

### 5. 输出结构

```
输出目录/教材名/
├── 章节结构.json                "按教材章节"识别出的各章页码范围与小节（可手工编辑；删掉则重新识别）
├── PPT/                        课件单独一个文件夹，文件名 = 课时标题 + PPT
│   └── 第1章_绪论_第1节PPT.pptx        AI 生成的课件，口播稿在每页“演讲者备注”里
├── 视频/                       口播视频单独一个文件夹，文件名 = 课时标题 + 视频
│   └── 第1章_绪论_第1节视频.mp4        一节一个（.tts_cache 配音缓存也在这里）
├── 课后习题/                    识别稿里的课后习题/思考题，单独出 Word
│   └── 第1章_绪论_第1节课后习题.docx   只放习题原文（识别不到就不生成这个文件）
├── 学习笔记/                    学习笔记单独一个文件夹，文件名 = 课时标题 + 学习笔记
│   └── 第1章_绪论_第1节学习笔记.docx   知识框架/公式/例题/易错点
├── 题库/                        题库单独一个文件夹，文件名 = 课时标题 + 题库
│   └── 第1章_绪论_第1节题库.docx       单选/多选/填空/解答 + 答案详解
├── 01_第1章_绪论_第1节/        每节课一个工作目录，识别稿在此
│   ├── 教材原文.md                    识别结果（含 LaTeX 公式，可手工修订；保留全文含习题）
│   └── 口播稿.txt                     纯文本讲稿，方便校对
└── 02_.../ ...（“按每节页数”模式下目录名形如 01_第1课_p1-p15/，标题里的空格写成下划线）
```

**课后习题单独成文**：识别时如果原文里有"课后习题 / 思考题 / 复习题 / 讨论题"这类小节（标题行，或短行里带这些词），程序会把这些小节整段切出来，按课时单独出一个 Word 放到 `课后习题/`；剩下的正文才拿去生成课件、笔记、题库，所以讲稿不会照本宣科念题目。切分是纯文本判断、不额外调 AI；识别稿没抄到习题标题就切不出来（`教材原文.md` 里能看到有没有），此时删掉它重跑识别即可。`教材原文.md` 始终保留全文。

**缓存与重跑**：产物本身就是缓存——`教材原文.md` 存在就跳过 OCR，`PPT/` 里的课件 + `口播稿.txt` 存在就跳过课件生成，`视频/` 里的视频存在就跳过合成，`课后习题/` 里的 Word 存在就跳过（没切出习题的课时不会生成文件），`学习笔记/` / `题库/` 里的 Word 存在就跳过出题。想强制重做某一步，删掉对应文件再跑；生成时日志会写明"已有…，跳过"。所以改时长/风格（在删掉课件后重跑）不会重复花识别费，重出视频也不会重复生成 PPT。

升级到本版后第一次重跑会自动**搬迁旧结构**：以前堆在课节目录里的 `xxx_课件.pptx` / `xxx_课件.mp4` 会被原地搬进 `PPT/` 与 `视频/`，`01_学习笔记.docx` / `01_题库.docx` 会被原地搬进 `学习笔记/` 与 `题库/`（日志提示"旧版产物已搬进…"），搬完即算缓存，不重复生成、不重复花钱。

两条额外提醒：

- `章节结构.json` 也是缓存：存在就跳过章节识别（不再调 AI），手工改它即可自定义章节划分（每章可选加 `sections` 小节数组让节边界对齐小节），删掉它则重新识别；
- **改了「切分方式 / 起始页 / 每节页数 / 最短节」后，节会重新排、目录名跟着变**：旧目录不会被复用（日志会提示"与本次切分不一致"），确认没用的旧目录可以手动删掉，避免混在一起；同名课时（少见）的产物会自动加 `_2` 区分。

生成的 PPT 是标准 pptx，可以直接用 PowerPoint/WPS 手工微调后再用"PPT → 视频"页单独出片。

## 二、PPT → 视频

1. **选择 PPT 文件** —— 可添加多个，批量处理
2. **输出设置**
   - 输出目录：留空 = 和 PPT 同目录
   - 页码范围：如 `1-18,19-36` → 生成 2 个视频；留空 → 整个 PPT 一个视频
   - 文稿来源：**正文**（读幻灯片上的文字）/ **备注**（只读演讲者备注）/ **备注优先**（有备注读备注，没有读正文）
   - TTS 音色 / 语速：默认晓晓女声；语速 `+15%` 加快、`-10%` 放慢
   - 无文字页停留 / 清晰度 / **帧率**：帧率默认 **10fps**。课件画面是完全静止的幻灯片，10fps 与 30fps 肉眼看不出差别，但编码快约 **5.9 倍**、文件还更小（实测 3 分钟成片：51 秒 → 8.7 秒，SSIM 画质反而略高，因为同样质量预算摊到更少的帧上）。追求"标准视频观感"或日后要加页面切换动画时再选 15 / 30。
   - **视频编码**：自动（用首启自检实测更快的）/ 显卡硬件编码 / CPU 软件编码，下面一行会写明自检结论和这次实际会用哪个编码器。「重新自检」随时可重测（约 5~15 秒）。硬编把活儿交给显卡、CPU 空出来更安静，软编在核显机器上通常更快。
3. **开始生成** —— 进度条和日志实时可见，可随时取消

输出命名规则：整个 PPT → `名字.mp4`；页码范围 → `名字_p1-18.mp4`。生成的视频为 1080p（按幻灯片比例）10fps H.264 + AAC，所有播放器通用。

**全程后台跑，不弹命令行黑框**：程序本身是无控制台的窗口程序，ffmpeg 与 PowerShell 子进程一律带 `CREATE_NO_WINDOW` 启动（`kouboppt/subproc.py`），不会在屏幕上闪一串黑框。导出幻灯片时 PowerPoint/WPS 的窗口仍会短暂出现——那是 COM 接口的要求（无窗口打开时 WPS 的 `Slide.Export` 会报 E_FAIL），导出完自动关闭。

## 运行日志

界面底部常驻「运行日志」，按颜色区分：绿色=成功、红色=失败/取消、橙色=警告、蓝色加粗=运行与阶段分隔。标题栏右侧四个按钮：

- **展开 / 收起**：日志区在 120px 与 420px 之间切换，方便翻长日志；
- **打开日志**：用系统默认程序打开本次的 `运行日志.log`（还没跑过则打开它所在的输出目录）；
- **导出日志**：优先把**含完整堆栈的 `运行日志.log` 逐字节复制**到你选的位置；没有日志文件时退回导出界面文本（没跑过任务也能用）；
- **清空**：只清界面，不动日志文件。

每次开始生成都会把日志**追加写入输出目录下的 `运行日志.log`**（「PPT → 视频」页用该页的输出目录，留空则用第一个 PPT 所在目录；「教材 → 课程」页用「输出目录」），并在日志首行写明该文件的完整路径。文件里每行带 `[时:分:秒]` 时间戳，每次运行之间用 `==== 时间 开始运行 ====` 分段，结束行汇总产出/失败/警告数——所以多次运行的历史都在，随时可回看。

**出错时界面只显示一行摘要**（`✘ 失败：异常类型: 首行信息`），完整的 Python 堆栈写进日志文件；反馈问题时把 `运行日志.log` 发出来即可。运行结束若产生过警告，日志末尾会补一句 `⚠ 共 N 条警告`。

首启的「本机视频编码自检」过程也会记入这个日志（自检页上会提示），所以自检浮层挡住日志区时也不用担心丢信息——关掉自检页即可回看。

## 设置记忆

所有选项自动保存在 `%APPDATA%\KouboPPT\config.json`，下次打开自动恢复（首启的编码自检结论存在 `enc_selfcheck`，所以只测一次；编码方式存在 `enc_mode`）。TTS 音频按内容缓存（「PPT → 视频」页在输出目录下 `.tts_cache`，「教材 → 课程」页在 `视频/` 下 `.tts_cache`），公式图片缓存于 `.eq_cache`（缓存键里带渲染规则版本，程序升级后公式会自动重画，不用手工删缓存），重复生成不重复合成。

## 已知边界

- **"按每节页数"不保证不跨章**：一节可能正好切在章的中间（日志会提示"跨过了章边界"，想严格不跨章请改用"按教材章节"）
- **"按教材章节"依赖书签或 AI 看目录**：都识别不到时，可在输出目录手工编写 `章节结构.json`（`chapters` 里写 `title`/`start`/`end`，可再加 `sections` 小节数组让节边界对齐小节）后重跑；没有小节信息的章退回按每节页数均分
- **接口网关超时（HTTP 524）**：AI 接口前面若挂了网关（如 Cloudflare），请求太重或模型太慢时会返回 524（服务器 100 秒没响应）。章节识别已改为低清缩图发送、超时自动换更小的请求；其他步骤遇到时稍后重试或换更快的模型/线路即可
- **模型输出不合规 JSON**：偶有模型把 LaTeX 反斜杠直接写进 JSON（如 `\(x\)`、`\frac`）或字符串里带裸换行——程序会自动修复后解析，`\(...\)` / `\[...\]` 也会当成公式正常渲染；实在修不了的会请模型自修一次，再不行就报错停下（重跑会接着已有进度继续）
- **回复被接口截断**：有些接口/中转会限输出长度（日志出现"撞到输出长度上限"）。为此内容页按每 3 页一次请求、题库每 8 题一次、笔记分上下篇，块小了就不容易被截断；万一还是截断，程序会从坏 JSON 里**抢救出已经写完整的页/题**继续用，并把模型的原始回复写到该节的 `AI原始回复.log` 便于排查（**只要检测到长度截断就会留档**，标注"（长度截断）"，不必等 JSON 解析失败）
- 公式渲染基于 matplotlib mathtext：支持常用数学命令和 matrix/cases/array/aligned/align/gathered 等环境（逐格渲染后网格拼装，所以环境本身不受 mathtext 限制）；公式在渲染前会先**自动归一**——模型/OCR 常写但 mathtext 不认的写法（`\le`/`\ge`、`\land`/`\lor`、`\frac1n`/`\frac12`/`\sqrt2` 这类省花括号写法、`\textbf`/`\textit`、`\displaystyle`/`\limits`/`\big`、`\bmod`/`\pmod`、`\underbrace`/`\xrightarrow`、`\lVert`、多行 `$$`、矩阵空格子、`x^22` 这种多位指数缺花括号）都会被换成等价可渲染写法，不再整行降级
- **漏写 `$` 的幂会自动补上**：模型在中文句子里常把科学计数法写成裸文字（如"5.00×10^22 个"），这时 `^` 会原样显示成尖号。程序会自动识别并包成公式（`$5.00\times10^{22}$`），单位/变量幂（`3cm^3`、`v^2`）同理；单字母按变量排斜体、多字母按单位排正体。已经在 `$...$` 里的内容一律不动
- `\text{中文}` 会自动改用系统中文字体渲染（`\textbf{中文}` 等同理）；**嵌在上下标或分式里的 `\text{}`/`\mathrm{}` 也能正常出图**——`a_{\text{Si}}`、`x_{\text{max}}`、`\frac{\mathrm{d}y}{\mathrm{d}x}` 这类旧版会整行渲染失败并退化成源码，现在能正确渲染（切分时只在花括号配平处切开，不会再切出 `\frac{` 这种残段）
- **中文出现在公式内部也能出图**：`E_{\text{总}}`、`v_{平均}=\frac{s}{t}`、`a_{\text{最大}}=\frac{F}{m}` 这类中文上下标，旧版会整行降级成纯文本 `E_总`（物理/化学教材里很常见）；现在自动切到"中文字体做数学字体"渲染——代价是丢掉数学斜体，但远比不出图好。**纯英文公式仍用 STIX 数学字体，字形不受影响**
- 多行推导可以直接写 `$$\begin{aligned} a &= b \\ &= c \end{aligned}$$`（环境逐格渲染，不受 mathtext 限制）；长矩阵/方程组两侧的大括号按公式字号切片拉伸，笔画粗细与正文一致（旧版是整体放大，长度一大就成了肥弧线）
- **渲不出的公式还有两级兜底**（`formula_fallback.py`，都离线，只有层①要调一次 AI）：① 请文本模型"只改写法不改语义"地把这条公式改写成 mathtext 能吃的形式再本地重渲——不少"渲染不了"其实是模型自己把 LaTeX 写坏了；② 仍不行就拿教材原页图（叠了百分比坐标网格）让视觉模型定位这条公式，按 300 DPI 裁下原图直接用——书上印着的就是最忠实的版本。结果按"行文本+颜色+是否独立公式"哈希落盘（`.eq_cache/公式兜底.json` + 图片），**成功和失败都记**，所以同一条公式不会反复花钱。两级都失败才降级成文本
- 万一仍然渲染不出来，**不会再往文档里写 LaTeX 源码**，而是降级成接近原文的可读文本：`a_{\text{Si}} = 0.543102\ \text{nm}` → `a_Si = 0.543102 nm`、`\frac{\mathrm{d}E_g}{\mathrm{d}P}` → `(dE_g)/(dP)`、`10^{22}` → `10²²`。该节课目录下会写出 `公式渲染失败.log`（运行日志里只显示第一条，完整清单看这个文件）；**PPT 与 Word（笔记/题库/课后习题）两侧都会在日志里提示**，Word 侧以前是完全静默的。**联网渲染服务**（把 LaTeX 发给第三方/内网服务换 PNG）留作扩展点，接起来只需在 `formula_fallback._rescue` 里插一层 + 一个配置项，默认不启用（不把教材内容发出去）
- 公式中极复杂的排版（多层嵌套环境）可能显示得不完美
- 模型偶尔会在题干、选项、公式里混进**不可见的控制字符**（XML 1.0 不允许写入）。这类字符在写进 Word/PPT/备注之前会被自动剔除（制表、换行保留），所以不会再出现"一个隐藏字符让整轮任务中止"的情况；万一仍然写入失败，运行日志会给出异常摘要与命中的字符码位（如 `U+000B`），并把出事的数据以 `repr` 形式留档到该节的 `AI原始回复.log`
- 老版 `.ppt` 会自动先转换成 `.pptx`（需要本机有 PowerPoint/WPS）
- 完全没有文字的页面会静默停留"无文字页停留"秒数（默认 3 秒）
- 渲染幻灯片时会短暂打开 PowerPoint/WPS 窗口，属正常现象，完成后自动关闭
- **换风格不会重做已有课件**：课件与口播稿齐了就算缓存（风格只在生成那一刻生效）。想让已经生成的课换风格，删掉 `PPT/` 里对应课件和该节的 `口播稿.txt` 后重跑；"自动"模式想重新选风格，删掉书目录下的 `PPT风格.json`
- AI 生成的内容建议人工过一遍：口播稿、题库解析都是草稿级质量，PPT 生成后可在 PowerPoint 里微调再出视频
- 每节时长由内容页数与讲稿字数共同决定；生成时会提示预计时长，偏差大时可在 PPT 里增删页后重出视频
